# 运维：换模型密钥（DeepSeek API key）

线上所有 AI 解读都走同一个 DeepSeek key。换 key 是**运维动作，不进仓库**：
key 只写在这台机器的 `/var/www/sqw.somtfly.com/.env`，代码与镜像里只有变量名。

这份说明是 2026-10-19 实际换 key 时踩完坑写的，命令都照抄可用。

---

## 0. key 在哪、怎么进到进程里

| 环节 | 位置 |
|---|---|
| 唯一真源 | `/var/www/sqw.somtfly.com/.env` 的 `DEEPSEEK_API_KEY=`（`.gitignore:2` 已忽略 `.env`） |
| 注入 | `docker/docker-compose.yml` 里 `DEEPSEEK_API_KEY: ${DEEPSEEK_API_KEY}`，涉及 **`backend` 与 `rag` 两个服务** |
| 读取 | `src/server/config.js:16` `apiKey: requireEnv('DEEPSEEK_API_KEY')` |
| 调用 | `src/server/auth-server.js` 里 `new OpenAI({ apiKey: config.deepseek.apiKey, baseURL: config.deepseek.baseURL })` |

仓库里**不该**出现 key 明文。核一遍：

```sh
cd /var/www/sqw.somtfly.com
git check-ignore -v .env          # 应输出 .gitignore:2:.env
git grep -l "sk-" -- . | head    # 应为空（空 = 没有明文进过版本库）
git status --short               # 应为空
```

## 1. 换 key 的完整步骤

**① 先备份 `.env`**（不要覆盖式手改，出错要能回滚）：

```sh
cd /var/www/sqw.somtfly.com
cp .env /tmp/env.bak.$(date +%s)
```

**② 先在外部验活新 key**，别到线上才发现 key 是错的/没额度：

```sh
curl -s -o /dev/null -w "%{http_code}\n" --max-time 20 \
  https://api.deepseek.com/v1/models -H "Authorization: Bearer <新key>"
# 期望 200；401/402 就别往下走了
```

**③ 只改 `.env` 里那一行**：

```sh
python3 - <<'PY'
import re, pathlib
p = pathlib.Path('.env')
new = '<新key>'
s = p.read_text()
s2, n = re.subn(r'^DEEPSEEK_API_KEY=.*$', f'DEEPSEEK_API_KEY={new}', s, flags=re.M)
assert n == 1, f'匹配到 {n} 行，先人工看一眼 .env'
p.write_text(s2)
PY
grep -n '^DEEPSEEK_API_KEY=' .env | sed -E 's/=(.{0,8}).*/=\1…/'
```

**④ 重建容器 —— `restart` 不够**。环境变量是**创建容器时**定下的，`docker restart` /
`pm2 restart` 都不会重读 `.env`：

```sh
docker compose -f docker/docker-compose.yml up -d --force-recreate --no-deps backend rag
```

**⑤ 必须 reload nginx（这一步最容易漏）**。nginx 配置里上游写的是 `backend:3301`，
没有 `resolver` 指令时它**启动时解析一次就缓存**；backend 容器重建后 IP 变了，
nginx 还往老 IP 发 → 全站 502（页面能打开静态资源，但所有接口挂）：

```sh
docker exec ai3000-nginx nginx -s reload
```

**⑥ 验证四件事**：

```sh
# a. 容器里确实是新 key
docker exec ai3000-backend printenv DEEPSEEK_API_KEY | cut -c1-8
docker exec ai3000-rag     printenv DEEPSEEK_API_KEY | cut -c1-8

# b. 真的能推理（用容器自己的 env + 同一个 SDK，不是只看变量）
docker exec ai3000-backend node -e "
const OpenAI=require('openai');
const c=new OpenAI({apiKey:process.env.DEEPSEEK_API_KEY,baseURL:process.env.DEEPSEEK_BASE_URL});
c.chat.completions.create({model:'deepseek-v4-flash',messages:[{role:'user',content:'只回四个字：收到测试'}],max_tokens:20})
 .then(r=>console.log('OK:', JSON.stringify(r.choices[0].message.content), 'model=', r.model))
 .catch(e=>console.log('FAIL:', e.message));
"
# 期望 OK: "收到测试"

# c. 站点与接口活着
curl -s -o /dev/null -w "%{http_code}\n" https://sqw.somtfly.com/
```

**⑦ 确认没泄漏**：`git status --short` 应为空（`.env` 被忽略，不会出现在这里）。

## 2. 回滚

```sh
cd /var/www/sqw.somtfly.com
cp /tmp/env.bak.<时间戳> .env
docker compose -f docker/docker-compose.yml up -d --force-recreate --no-deps backend rag
docker exec ai3000-nginx nginx -s reload
```

## 3. 已知的坑（都是这里真实踩过的）

- **只 `restart` 不重建容器**：key 不会变，页面照旧报错，而且看起来「改过了」。
- **忘了 reload nginx**：全站 502，但首页 HTML 是静态的照常打开 —— 很容易误判成后端崩了。
  排查顺序先看 `docker exec ai3000-nginx tail -5 /var/log/nginx/error.log`。
- **别用 `/api/status` 做健康检查**：这个端点已经不存在了（2026-10-18 之后的版本里没有），
  访问会返回 `{"error":"Not found"}`，与「后端挂了」长得不一样，但同样是 404。
  健康检查用 `GET /`（静态）加一次真实接口调用，或者按上面 ⑥b 的方式直接打模型。
- **`rag` 也要重建**：它同样注入了 `DEEPSEEK_API_KEY`，漏掉就是两个服务用两个 key。
- **别把 key 写进 `docker-compose.yml` / 代码 / 提交信息**：那等于公开。仓库里只有
  `${DEEPSEEK_API_KEY}` 这个占位符。
- 旧 key 换下来后，如果别处也在用，记得去控制台把它作废，不要只换一处。
