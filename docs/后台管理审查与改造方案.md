# 后台管理审查与改造方案

## 1. 范围与结论

状态：已完成 React + Ant Design 迁移并发布。隔离验证通过 176 项单元测试、44 项后端测试与 29 项后台/首页浏览器测试；发布产物与容器哈希一致。写操作均使用 mock 验证，未删除真实业务数据或调用付费 AI。用户追加确认：去除后台小程序相关入口/来源统计和服务器状态展示，保留小程序账号与业务数据；所有屏宽采用左上角菜单按钮打开左侧抽屉，不做顶部悬浮 Tab / 横向栏目导航。后续确认：手机端改用任务卡片，桌面保留表格；仪表盘增加真实会员分布和最近注册用户。用户已明确允许永久删除账号及全部关联业务数据，并要求个人设置提供自行注销入口；这批追加改动正在隔离验证，尚未发布，不执行真实账号删除验收。下文审查证据为改造前快照，不代表改造后行号。

建议：保留 Vite + React 和现有 Node REST 后端，在 `/admin/` 内采用 **Ant Design + 按需 ProComponents**，把当前字符串 HTML / window 内联事件宿主改成真正 React 管理页面。不是自己重造表格、表单、弹窗，也不是搬入整套独立平台。先修安全和数据一致性，再改操作结构与视觉。

## 3. 成熟方案比较

| 方案 | 适用与成本 | 本项目决定 |
|---|---|---|
| Ant Design + ProComponents（MIT） | 社区成熟的后台组件体系，布局/表格/搜索表单/详情/弹窗可复用；不强制替换后端与数据协议 | 首选。Ant v6 对 React19 有官方支持；ProComponents 具体版本与 Ant 兼容矩阵须单独核对，不默认全部最新即可混装 |
| Refine（MIT 核心）+ Ant Design | 提供 resource/dataProvider/authProvider/query 生命周期，适合持续扩张的 CRUD 后台；引入资源、路由与缓存模型 | 备选。若后续页面显著增加再采用，不与 ProComponents 路线同时叠完整框架 |
| React-admin（MIT 核心） | 成熟资源管理框架，dataProvider/authProvider，默认 MUI/Emotion；部分扩展属于商业产品 | 可用但非首选：需要更大视觉与资源协议迁移，现阶段收益不如按需接 Ant 组件 |
| Tabler React | 旧 React 仓库已归档，不能用知名度替代维护证据 | 不选 |

官方资料：
- Ant React19 / v6：https://ant.design/docs/react/migration-v6/
- Ant 主题：https://ant.design/components/config-provider/ ，表格：https://ant.design/components/table/
- ProComponents MIT/源码：https://github.com/ant-design/pro-components ，布局：https://procomponents.ant.design/en-US/components/layout/
- Refine：https://github.com/refinedev/refine ，资源适配：https://refine.dev/core/docs/data/data-provider/ ，React18/19：https://refine.dev/core/docs/migration-guide/4x-to-5x/
- React-admin：https://marmelab.com/react-admin/ ，协议：https://marmelab.com/react-admin/DataProviderIntroduction.html
- Tabler React 归档状态：https://github.com/tabler/tabler-react

重要版本门槛：官方 ProComponents 3.0 变更文档要求 antd 6+（https://procomponents.ant.design/en-US/docs/api-changes/），但本轮 npm 搜索仍显示 2.8.10，不能把文档版本等同于可安装发布版。实施先核实仓库实际可获取版本和 peer 矩阵；若 v3 未发布或不兼容，则只用 Ant Design 核心的 Layout/Table/Form/Modal 等成熟组件，不强塞旧版 ProComponents，也不自行重造这些组件。

实施采用固定版本 antd 6.0.0 / @ant-design/icons 6.0.2（MIT），复用核心 Table、Form、Modal、Drawer、Menu 等组件，未引入 ProComponents 或第二套后台框架。React19.3.1 / Vite8.3.4 隔离构建通过；后台独立 JS 约 841 kB（gzip 约 267 kB），构建存在大包提示，依赖仅由 admin 入口引用。

## 4. 后台结构与交互

不增加无依据的复杂权限系统，先保持现有管理员权限。菜单分组：

- **概览**：核心业务数量、积分累计/近七天；删除服务器状态/到期展示、小程序来源切换及相关展示。不展示伪健康指示。
- **用户与权益**：用户列表 → 用户详情；详情显示稳定账号标识、手机号、等级、今日已用/上限/剩余、累计消耗及重置口径。调整今日用量不能叫“充值”，不暗示改了累计账本。
- **业务记录**：命盘、梅花、六爻；按用户/日期/类型筛选，表格直接看记录，不强迫逐层点巨大用户卡片。八字咨询管理是后续可选资源，不能用没有接口的空菜单充数。
- **内容与 AI**：建议、参考书籍、Prompt。书籍编辑正文与入库状态分开；入库显示 pending/running/succeeded/failed 的真实能力，缺任务接口先标明限制。
- **系统设置**：密码、安全会话、真实可管理的配置。不把所有“信息展示”都堆设置里。

所有屏宽：左上角菜单按钮 → 左侧 Drawer 菜单 → 选择栏目后关闭。禁止顶部悬浮 Tab、顶部横向栏目导航；顶栏只放菜单按钮、当前页标题和必要账号操作。用户列表采用成熟搜索表单、分页与操作列；数据少可明确使用前端分页，数据增长后再由服务端提供分页/总数，不能假称已有服务端分页。去除小程序来源切换/展示及服务器状态卡片，不删除任何相关业务数据。

手机（≤600px）：左上抽屉菜单，用户、业务记录和书籍采用带字段标签的紧凑任务卡片，常用操作直接可达；桌面保留 Table。仪表盘会员分布使用两列表格，最近用户手机用卡片、桌面用表格。危险删除先展示账号及清空范围，要求完整输入稳定账号标识再提交；失败保留确认内容，不默认开放批量删用户。个人注销要求重新验证登录密码、完整账号确认及知悉后果，服务端明确确认成功后才清除登录态；无密码账号暂不开放自行注销。

视觉：保留青绿主色 `#1f6b5e`、浅背景、中文与清晰密度；后台以阅读和操作效率为先，不照搬前台大留白卡片。通过 ConfigProvider 统一色彩/字号/圆角/间距，禁止一套 Ant 默认蓝、一套自写金色同时存在；后台 CSS 与依赖只进入 admin 入口，避免污染前台。

## 5. 实施顺序及验收

1. **安全底线**：移除内联事件注入；修稳定身份与删除等待/事务；补恶意字符串、phone≠username、数据库失败、未授权测试。确认删除范围后再实施该破坏性路径，不执行真实删除验收。
2. **最小技术验证**：只做后台壳 + 用户只读表格，接现有 API，主题统一；验证固定依赖组合、样式隔离、移动端、包大小。不一口气重写八个页面。
3. **用户与权益写操作**：详情抽屉、等级和今日积分编辑、统一请求状态。保留 10000 token=1 积分、10/50/无限、北京时间日界与四位小数规则。通过 mock 正常/失败/401/403/409/503 验证。
4. **其余资源逐页迁移**：命盘/卦例 → 书籍 → Prompt/建议/设置。每页先核 API 真实字段，再用成熟组件；清除对应旧字符串逻辑，不长期保留两条主路径。
5. **发布**：隔离 Vite 输出、mock 写/付费 AI；通过后仅 sync.sh 发布，核对哈希/HTTP/浏览器。每个可验收阶段及时 commit，不在 DNS 故障时把 push 未完成报成功。

验收覆盖：登录与会话过期、深链刷新、列表加载/空/错误/重试、筛选与分页保留、键盘导航/弹窗焦点回归、390/768/1280 宽度、保存防重/失败留草稿、危险操作取消/失败/成功及关联范围、前台样式与功能不回归。实施已完成上述核心流程的 mock 浏览器回归：登录失效、稳定账号标识、积分/等级、Prompt 独立草稿与恢复默认、书籍正文和失败重试、记录删除失败重试、390/768/1280 抽屉导航及注入字符串。追加的永久删除路径已通过事务回滚、十类业务表清理、账号身份隔离、删除与写入互斥、旧登录凭据失效和用户二次确认的 mock 验证；密码重置在共享锁内核对账号创建时间，拒绝向已删除后重建的账号写入。旧 JSON 登录恢复路径已撤除，数据库是账号唯一来源。没有执行真实业务删除、书籍入库或付费 AI。
