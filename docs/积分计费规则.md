# 积分计费规则

## 单位与权益

- 输入与输出 token 合计，每 5000 token = 1 积分（换算比例在后台「系统设置」里可调，改后即时生效；历史记录按当前比例折算展示）。内部使用整数 token 单位，展示最多 4 位小数，不按次向上取整。
- 普通用户（tier 0）：每周 10 积分；普通会员（tier 1）：每周 50 积分。不乘以七。
- 账期为 Asia/Shanghai 自然周，北京时间周一零点刷新，未使用的周额度不结转。跨周请求计入开始时账期。
- SVIP（tier 2）不限量，仍记录真实用量，但不扣永久积分。
- 永久积分仅由后台人工追加，不过期，不因每周刷新或会员组变化清零。获取永久积分或升级用户，请添加微信 **cqsomt** 办理；不在界面承诺价格或支付方式。
- 使用顺序：先每周额度，不足部分再扣永久积分。两者都不足时拒绝新请求。修改会员组不清除已经发生的本周消耗。

## 后台与账本约束

- 后台不再修改“今日已用积分”；调整会员组决定周额度，添加永久积分使用独立操作。
- 发放要求正数、最多四位小数、原因和唯一请求标识，记录管理员及时间；同一操作重试不得重复增加余额。
- 消费继续使用现有共享锁、额度预检、真实模型 usage 和事务结算；一笔消耗记录其周额度与永久余额扣除情况。
- 保留旧每日汇总及旧消费流水，不删除账号、会员组、命盘、卦例、聊天或咨询，不把历史消费伪造成永久积分。
- 本次只是账期与余额来源扩展，不引入支付平台、自动充值或自动续费。

## 展示与兼容

- “我的”分别展示本周余额与永久积分，并提供“如何获取永久积分”“如何升级用户”说明。
- 聊天回答仍只显示本次积分消耗总量，不把扣除过程堆进正文。
- 所有主站 AI 入口统一使用服务端额度；游客原有体验规则不变。
- 历史回答和当时尾账不重写；历史 Token 标签不改成积分。
- 注销账号仍按既定规则删除其关联积分数据，不能因为新增余额表留下孤立记录。

## 已知边界

- 上游提供 usage 时按真实输入输出结算；缺失时沿用估算回退，不承诺与提供商账单逐 token 一致。
- 输入预估并非提供商 tokenizer，真实成本高于预估时仍如实入账；永久余额最多扣到零，不因估算偏差制造负余额。不能宣称绝对无超额。
- 本周已用记录本周实际消耗总量（包括超出周额度、由永久余额支付的部分）；当周切换等级不会清除这些用量。
- 中途停止、部分输出的计费政策不在本轮另改；咨询继续独立返回生成、结算、保存状态。
- 测试必须模拟模型及业务写入；真实发放、扣费或删除账号不属于自动测试。

## 实施状态

本轮实现周额度、永久余额与人工发放账本；使用隔离构建和模拟模型、数据库及写接口验证。发布后的真实发放与扣费仍需管理员按实际业务操作核验，不以自动测试创建真实余额或消费。
