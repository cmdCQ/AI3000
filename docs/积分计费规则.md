# 积分计费规则

## 单位与额度

- 输入与输出 token 合计，每 10000 token = 1 积分。内部保留整数 token，展示最多 4 位小数，不按次向上取整。
- 普通用户（tier 0）：每日 10 积分；普通会员（tier 1）：每日 50 积分；SVIP（tier 2）：不限，仍记录实际消耗。
- 账期为 Asia/Shanghai 自然日。北京时间零点进入新的每日账户，余额不结转。跨零点请求计入开始时的账期。
- 管理员修改等级立即影响每日额度，不清当天用量。调整“今日已用积分”仅影响当天余额，作为调整流水留存，不改累计真实消费。

## 数据与接口

- `points_usage` 独立保存收费及管理调整流水；`points_daily` 为每日汇总；`users.token_used` 保留原始累计 token。删除咨询、聊天或卦例不删除计费流水。
- `/api/user/points` 返回今日消耗、额度、余额、累计消耗、等级、账期及刷新时间，均由服务端计算。
- 后台消费统计按实际收费流水统计；近七天为包含今天的七个北京时间自然日，不再按用户最后活跃时间筛选终身消费。
- 主站聊天、梅花/六爻及追问、旧八字解析、新八字咨询共用用户级生成锁、额度预检及结算服务。余额不足返回 429，服务不可用返回 503，不将错误正文当成功解读保存。
- 八字咨询沿用请求标识幂等；独立计费流水不随咨询删除。其他旧接口目前无客户端重试幂等协议，每次明确发送视为新请求。

## 兼容与范围

- 原有游客免费体验规则保持，不清 `anon_usage`。
- 历史回答与当时的尾账不重写，不把历史 Token 标签改称积分。旧版本已经写成“积分”但实际是 token 的历史账行无法仅靠文字可靠区分，不自动重算。
- 本轮只清用户旧计费用量，保留账号、等级、命盘、卦例及咨询/聊天记录。新流水从切换时开始，不能伪造此前每日记录。
- `/api/personal/chat` 属于独立个人站代理，在本项目未发现前端调用方，本轮不改其匿名权益；RAG 内部生成接口未作为主站计费入口发布。

## 已知边界

- 上游提供 usage 时按输入与输出真实值结算；缺失时沿用现有估算回退，不承诺与提供商账单逐 token 相同。
- 输出预算会根据剩余额度及输入估算缩减，但输入估算不是提供商 tokenizer；单次实际输入高于估算时，实际消耗仍如实入账，余额最低显示零，不能声称绝对无超额。
- 不在本轮另改中途停止/部分输出的历史收费政策：普通聊天已有非空输出可能计费；八字路径断线不收费，未完整生成但有输出可能收费。咨询明确返回独立生成、结算、保存状态。统一停止收费政策需要单独确认。
- 尚未进行真实付费模型调用验收；测试使用模拟模型与模拟业务写入。
