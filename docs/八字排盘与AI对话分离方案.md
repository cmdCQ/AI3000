# 八字排盘与 AI 对话分离方案

> 状态：已按用户要求撤销本轮分离改造，源码与线上已恢复至分离前行为；保留此前选择页/UI 改进及 AGENTS 精简。本文仅保留为历史方案，以下实现和验证记录描述回滚前状态，不代表当前交付。用户已确认：严格纯排盘（不展示旺衰、格局、喜用神及吉凶判断）；保留一次游客非综合解读及登录承接；首页继续现有弹窗。以下原方案的推荐项如与此不同，以此确认结果为准。
> 实施范围：详情已移除生成模块，保留旧解析只读回看与带盘对话入口；游客使用独立临时出生资料入口，不放宽已保存命盘权限。不新增数据库表、不删除旧记录，也不把一用户 JSON 历史称作独立多会话。
> 已实现：详情导航携带 chartId，服务端校验归属并重建命盘；首问和追问稳定携带同盘上下文，同盘完整历史成对恢复；八字 opt-in events-v1 区分完成/截断/失败，正文和积分分帧，仅完整回答存入账号历史。游客沿用签名 cookie/IP 闸门，登录后恢复浏览器本地资料与草稿而不自动发送。仍沿用现有计费，部分输出不承诺免费；未做独立会话、快照、跨设备并发与实模型质量验收。
> 最新验证：前端单测 170 项通过；后端真实 handler 的 VM 集成测试及领域 helper 共 25 项通过，覆盖归属、额度、正常/截断/空流、结算/保存失败、游客额度和断开；全量隔离浏览器 164 项通过。写接口与模型均模拟，未调用付费 AI 或写入真实业务记录。发布产物与容器哈希一致（前端 c2605fee59c6、后端 8400326f8f15）；线上静态产物的 66 项关键浏览器流程通过（业务 API 与模型模拟）；真实匿名同盘历史请求返回预期 401，确认后端新分支生效。页面指纹均无 problems；游客路由由旧登录壳变成出生资料表单，梅花/六爻少载入一份不再依赖的八字样式，时间文字哈希变化不作为等价证据，已有视觉与行为回归通过。
> 本方案替代上一版整改计划中的“八字详情内继续优化解析卡片、按五方面分别解读”方向；上一轮已完成的选择页、错误处理和测试保护仍可复用。

## 一、目标与推荐结论

**八字模块负责把盘排清楚；AI 对话负责围绕盘解读、提问、追问。**

不是把旧解析卡片换个位置，而是改变用户的使用方式：从“点一个栏目生成报告”，变成“选定一张盘，围绕自己的问题连续交流”。

推荐首版包含：

1. 八字详情只呈现出生资料、四柱与排盘数据，不再放生成按钮、五方面解析标签、追问框、积分与 AI 正文。
2. 保留一个明确的跨页入口“带此命盘去 AI 对话”，跳转后先预览命盘，不自动生成或扣费。
3. AI 对话增加八字命盘选择、固定可见的当前命盘、快捷问题、连续追问、可恢复的会话历史。
4. 一段八字会话绑定一张命盘，切盘新建会话，避免甲盘和乙盘的上下文串在一起。
5. 旧八字解析保留为只读记录，不删除，不冒充新的多轮聊天。
6. 梅花、六爻现有排盘及详情内解卦入口保持不动；共用对话体验的改动要做回归。

### 不做什么

- 分阶段实施不顺带改首页整体设计、排盘算法、真太阳时规则、模型供应商或价格。
- 首版不接入模型自主调用全部工具，不增加“多命盘同时比较”、语音、文件上传、联网研究等旁支。
- 不继续强制所有回答使用“评分 + 全套栏目”；不把旧的五份模板原样搬进对话。
- 不承诺健康、投资或未来事件预测必然成立，不展示模型内部思维链。

### 对想法本身的评估

结论：方向值得采用，但入口迁移本身不是解读质量提升。

- 收益：排盘不被长报告打断，用户可按自己的问题交流，专业用户与入门用户各取所需。
- 主要风险：多一次跳转、空白输入框让新手不知问什么、换页丢盘、追问失忆、旧记录入口消失。
- 成立条件：一步带盘、当前盘清楚可见、快捷问题可编辑、每轮稳定带盘、历史可恢复；先接通再撤旧模块。
- 体验验证：用“初次读盘”“问指定年份并追问”“隔天回来继续”三项任务比较现有与新原型，观察能否独立完成、是否重新选盘/解释背景、是否知道当前讨论对象；不以页面更简洁或对话字数更多单独判成功。
- 梅花/六爻的一事一问流程已获认可，不为统一外观强行一起迁移。

## 三、八字页：只排盘的具体边界

### 推荐信息结构

```text
返回命盘列表                         四柱八字
姓名 / 性别 / 出生时刻
四柱主盘
[带此命盘去 AI 对话]
基本资料 / 四柱细表 / 大运时间表 / 流年干支
术语说明（可折叠，仅解释术语，不判断个人吉凶）
```

跨页按钮是导航，不是解析模块；不在按钮下面预埋聊天框、生成进度或报告。排盘失败时不允许带一份失败/残留盘进入解读。

### 数据与解析分层

| 留在排盘页 | 推荐迁出排盘页，放到对话按需解释 |
| --- | --- |
| 出生资料、当前计算口径、四柱、藏干、十神、纳音等盘面字段 | 命局提要、人生判断、旺衰白话论述 |
| 大运干支、起止年龄/年份、流年干支；“当前大运”时间定位 | 每步大运好坏、吉凶理由、流年总结、未来五年好坏标签 |
| 五行数量等可核对统计，明确统计口径 | 喜用忌结论、推荐行为、事业财富婚姻健康推断 |
| 合冲刑害等关系名称（中性呈现，不红绿判吉凶） | “冲主变动”等针对本人的应用解释与预测 |

“旺衰、格局、喜用神”虽然可能由规则算法生成，也属于解释性结果，不能当成不可质疑的事实。但不建议为了严格分离而一刀切删除专业参考：可在排盘页折叠呈现并标注“规则推断，可能存在流派差异”，个人化白话与应用建议进入对话。上表迁出范围是严格分离选项，不是已确认的删除清单；最终保留范围待产品确认。

**这是待确认的产品边界，不在规划阶段删除现有内容。** 不改底层计算，只拆显示层与供模型使用的数据层。真太阳时目前仅有显示逻辑的事实必须准确展示，不在本次迁移中悄悄改变用时口径。

## 四、三条核心用户流程

### A. 从八字详情进入

1. 用户排出/打开自己的盘，点击“带此命盘去 AI 对话”。
2. 到 `/ai-chat/`，顶部显示已选盘摘要，输入区给出可编辑问题建议。
3. 若有同盘历史，显示“继续最近对话 / 新建对话”，由用户选择，不静默复用旧话题。
4. 用户输入问题或点快捷问题后，内容先填入输入框，点击发送才发出。
5. 服务端校验命盘归属、重建盘面，随后解读；之后每次追问都自动携带同一命盘上下文。
6. 返回看盘时回到来源命盘；再次进入可恢复会话。

### B. 从 AI 对话进入

空态提供“直接提问”和“选择命盘”两个清晰入口。选择器新增“四柱八字”，保留梅花、六爻，避免把“分享排盘”误理解为对外公开。

选择八字时：列表展示姓名、性别、出生时间；支持空态创建、加载失败重试、取消不改变会话。用户确认后生成八字会话与命盘摘要。发送请求失败时保留问题与选盘状态。

没有盘却问“我的八字如何”时，先引导选盘/排盘，不编造数据。首版不让模型自由猜出生参数并建盘。

### C. 下次接着聊

“历史”打开会话列表，显示题目、命盘名称、更新时间；点开恢复消息和当前盘，不只恢复文字。新建会话不等于清空所有记录。删除只作用于明确选中的会话，二次确认且失败可见。

旧的“一键清空全部”不再作为主操作。整个历史、其他盘、其他术数记录不能被一次新建或重试误删。

## 五、AI 对话新体验

### 布局草图

```text
返回       与「某某」聊八字         历史 / 新建
当前命盘：某某 · 男/女 · 出生时间     查看盘面
─────────────────────────────────────
你：我想看某年的学业节奏……
AI：先给主要判断，再按问题展开……
    [复制] [重新回答（将重新消耗积分）]
─────────────────────────────────────
建议追问（可选、点击只填入）：
[先看整体] [看指定年份] [解释一个术语]
[输入你的问题……]                 [发送]
```

- 当前命盘保持可见但紧凑；展开才显示完整生日与四柱，避免手机满屏都是卡片。
- 不再用“综合/事业/财运/婚姻/健康”作为五个相互割裂的答案容器。它们可以是可编辑的问题建议，不是固定报告模板。
- 首句建议举例：“先帮我读懂这张命盘”“结合我的情况，分析指定年份”“解释盘中的某个术语”。涉及年份要求用户确认，不硬编码过期年份。
- 回答以“要点 → 依据 → 展开 → 可执行建议”作为表达倾向，不强制每次四段；追问只回答新增问题，不重复整份报告。
- 不知道职业、在读状态、目标年份就询问或用条件句；可从出生时间算年龄，但不能把年龄直接当成在读/在职事实。
- Markdown 标题、列表、表格正常渲染；宽表在消息内部横向滚动，不撑破页面。不引入夸张评分、动画或多套视觉体系。
- 等待态只说真实阶段：“准备命盘 / 等待回复 / 正在生成”，不能假装展示模型内部思考。
- 用户上滑时不强制拉回底部；提供“回到最新”按钮。移动端处理软键盘、安全区、长输入、中文输入法 Enter 组合态与按钮触控区。
- 生成中可停止，禁止同会话并发发送；停止显示“已停止”，不伪装成完整成功。切换会话要明确停止当前请求，不让旧流写入新会话。
- 明确区分登录失效、额度不足、网络失败、空回复、部分输出、正常完成；错误响应不作为 AI 正文保存。
- 失败允许重新发送原问题；“重新回答”生成新的 attempt，保留旧答案，不覆盖或隐式重复扣费。

### 首页入口建议

推荐把首页 AI 入口改为导航到同一个 `/ai-chat/` 页面，保留首页其余版式。这样浏览器返回、会话链接、软键盘行为和命盘来源更一致。

此项属于待确认体验调整；若保留 iframe，也必须共享同一会话协议并测试关闭/重开、返回、停止，不建设第二套聊天状态。不要为了移除 iframe 顺带重做首页。

## 六、会话、命盘与模型上下文

### 1. 命盘不是一次性附件

推荐增加持久会话，而不是继续往用户唯一 JSON 长数组追加。

- `conversation`：id、user_id、mode（general/bazi 等）、title、source_chart_id、绑定盘面快照/版本、created_at、updated_at。
- `message`：id、conversation_id、role、content、status、request_id、attempt_id、parent_message_id、created_at；usage/计费结果与回答状态关联。
- 命盘快照：实际参与计算的出生参数、计算口径、结构化盘面与版本/哈希；不无限重复存入每条消息。
- 消息分页读取；最近会话列表有边界；旧消息可以继续加载，不因模型上下文预算不足而从历史界面消失。

字段是逻辑设计，实施时结合现有数据库确定具体类型、索引和事务。不做无必要的全站数据库重构。

### 2. 安全传盘与明确绑定

已保存命盘只传 chartId 等引用，由服务端按当前用户读取、校验归属、调用唯一排盘函数；不相信客户端传来的八字结论或盘面 HTML。管理员查看他人的盘不能自动获得代聊权限。

跨页 URL 只放引用或短期 opaque handoffId，不放姓名、生日、完整盘面、JWT。未保存排盘可在确认临时盘流程后使用同源短期交接，登录恢复一次，不自动发模型请求；若首版只支持已保存盘，UI 必须明确要求先保存，不能悄悄丢失资料。

命盘被编辑：旧会话继续显示并使用创建时快照，提示“源命盘已更新”，使用新版须新建会话。命盘被删除：历史按原授权保留快照并提示源记录已删；删除会话可删除该会话快照。以上是推荐保留策略，需与用户确认，不默认级联删除历史。

切换盘新建会话；首版不支持同一八字会话内混入第二张盘、梅花卦或六爻卦。

### 3. 每次追问都要稳定带盘

服务端构建消息：系统规则 → 当前盘事实 → 可选规则推断/检索资料 → 会话摘要（如需要）→ 预算内最近完整问答 → 当前问题。

- 命盘事实始终保留，不能随“最近三轮”被截掉。
- 历史用真实 user/assistant 消息结构，不把所有历史压进一个 user 字符串；用户文本、历史、检索资料一律当数据，不能冒充系统指令。
- 长对话按 token 预算裁剪完整回合；可用可追溯摘要，不能每条硬截 200 字。摘要不得发明命盘结论；不足时说明限制。
- 目标年份、所在时区、当前日期由服务端明确注入；缺少指定年份的流月数据先补充同一计算链路，不能让模型自算凑全。
- 八字模式不触发数字起卦，也不使用“先要三个数字”的通用规则。普通聊天的自动数字起卦建议改为显式动作；梅花专用快速起卦仍保留。
- 不要求先启用 tool calling；当前工具尚未接通，首版由确定性服务端路由完成查盘与构建上下文，风险更小。

## 七、后端迁移方式

### 统一执行路径，而非接口套接口

1. 主聊天 `/api/chat/send` 增加明确 bazi 模式及 conversationId/requestId；每次请求校验会话归属和绑定盘。
2. 提取可测试的八字上下文构建层，复用 `baziChartFromParams`、现有可靠计算及八字 RAG，不复制一套排盘算法。
3. 将“事实数据”“规则推断”“prompt 指令”分开；当前 `/api/bazi/paipan` 返回的 text 是完整报告 prompt，不应直接当命盘事实或对话正文。
4. 构建对话式八字 system/prompt，不直接套旧固定全报告模板。用户此前参考的外部样本只作表达质量参考，不把第三方接口变为生产依赖。
5. 原五方面 prompt 整改不再作为前置任务；最终提示词仍需单独校准。方案不宣称已经完成用户尚未提供的专项 prompt。
6. 旧 `/api/bazi/parse` 在兼容期保留，旧页面/缓存客户端仍能用；新页面不再调用。若合并内部执行代码，必须保留旧鉴权/游客/响应契约，不能盲目代理到登录必需的聊天端点。
7. 兼容期后再根据使用证据决定下线，不在首版删除端点或旧记录表。

### 流式、状态与计费

当前是声明 event-stream 的裸文本流和积分尾巴，不是真正的事件协议。推荐为新对话提供显式版本化协议（如请求协商 v2），逐步返回 meta/delta/done/error 等事件；旧梅花、六爻面板继续旧协议，不能全站一刀切。

- done 才代表正常完成；部分文本保留但标记 interrupted/failed，不能只凭“有正文”判断成功。
- requestId 幂等：网络重送同一请求不能再创建回答或重复扣费；主动重新回答使用新 attempt。
- 同会话服务端限制并发，跨设备也不能因前端按钮状态而绕过。
- 沿用现有额度体系与真实 usage 优先的原则，不暗改费率。开始前查额度，结算与 usage ledger 关联；停止/失败/未返回 usage 的实际扣费政策需先确认，UI 不承诺“失败一定免费”。
- 断开/停止及时取消上游；已产生的成本如何结算须与产品规则一致，不能既记账又告诉用户没消费。
- 保留 `X-Accel-Buffering: no`；绝不 gzip event-stream。旧积分尾巴仍由统一函数产生，新协议将 usage 独立于正文。
- 保持现有模型配置为基线，用同组问题验证思考开关、首字等待、正文截断与费用；本次不把切模型当作迁移。

## 八、旧记录与权限：不静默丢东西

### 历史迁移

- 现有 chat_history 先以“历史对话（旧版）”只读入口保留，不冒充已经正确绑定命盘的会话；可在迁移校验后形成旧版会话副本，原数据不破坏。
- 旧 bazi_analyses 按盘、方面、时间提供只读列表，放在 AI 对话的“旧版解析”中，不继续放八字排盘页。
- 看旧记录不调用模型、不扣费；如需“基于这份记录继续聊”，先绑定经过校验的盘，明确该记录是旧回答而非事实，可引用后显式发送。
- 没有 chartId 的旧记录不猜测绑定，单列“未关联命盘”。原追问未落库，不能宣称补回不存在的记录。
- 迁移可重跑、有旧新 ID 映射、计数核验与失败报告；权限过滤始终按 user_id，不因只读就开放。

### 待确认的权限变化

主 AI 对话目前要求登录，旧八字详情却有游客一次非综合解读。推荐首版统一“排盘免费、AI 对话登录后使用”，但这会改变游客权益，**实施前须确认，不能默认取消**。

若要求保留游客一次：应做独立匿名会话与现有签名额度闸门兼容、禁止查看他人已存盘、登录后安全合并临时会话；不是简单删掉 chat/send 的鉴权。此分支会增加测试与安全工作量。

## 九、实施顺序与放量条件

| P0 产品边界与契约 | 确认纯排盘范围、游客策略、首页入口、旧记录策略；原型与接口/schema | 先定清楚，不直接删卡片 |
| P1 会话基础与测试 | 新会话/消息持久化、归属校验、命盘快照、历史恢复、请求幂等；模拟流 | 刷新/切会话/重复请求不串盘不重扣 |
| P2 八字对话接通 | 服务端八字路由、盘面上下文/RAG、问题建议、连续追问 | 指定盘与模型上下文一致；后续追问不丢盘 |
| P3 对话体验 | 状态机、停止/重试/重答、滚动、移动端、旧记录只读入口 | 错误与成功可区分，输入不丢失 |
| P4 切换八字页 | 移除 AI 挂载与解释性呈现，保留排盘导航；按确认结果调整首页入口 | 新流程可用后才撤旧 UI，不留能力真空 |

数据结构使用增量方式添加，不破坏现有表。回滚新前端/路由不能删除新会话与积分账本；旧读路径和兼容解析仍可用。数据库回退不使用破坏性 drop。

### 当前最小闭环的发布门槛

当前先接入已保存命盘的登录用户对话，并保留旧详情解析；不把这一阶段当作完整迁移。

- 新入口只有排盘成功后可用；管理员代看和失败盘不提供带盘入口。
- 对话页先读取授权命盘并展示摘要，每轮只传引用；禁止数字起卦和混入其他术数附件。进入、选盘和重试预览不生成、不扣费。
- 后端必须复用现有聊天执行与积分路径，不能增加跳过额度或计费的免费模型旁路；上下文必须用真实排盘结构测试，不能以虚构 `chart.bazi` 字段掩盖空盘。
- 现有裸文本流不能可靠区分正常完成、截断、失败；现有额度预检与 JSON 历史读改写也有并发风险。须补正常/部分/失败/停止判据与隔离测试，并确认实际成本结算政策后，才能正式切换。未确认前不擅自承诺失败免费。
- 单用户 JSON 只能提供有边界的同盘历史兼容，不能满足快照版本、独立会话、并发和持久状态要求；这些能力完成前不撤旧入口、不宣称完整历史恢复。

## 十、验收清单

### 用户可感知的完成标准

- 打开八字详情，只看见排盘与资料，不出现 AI 生成/方面切换/积分；看盘不发 LLM 请求。
- 点击“带此命盘去 AI 对话”能看见正确命盘，点击发送前模型请求为 0。
- 问“2026 年学业”，不会因为数字触发起卦；追问“那下半年呢”仍针对同盘、同年及已有问题背景。
- 切到另一张盘必须新会话；旧回答不会混到新盘；回到旧会话可继续。
- 当前已实现：账号按 chartId 恢复完整问答对；游客在同一浏览器恢复临时资料、问题及本地回答。未完成回答不写入账号历史；独立会话的新建、删除与持久状态恢复属于后续能力，不作为本轮已交付项。
- 查看旧解析不生成、不扣费，且能分清旧记录与新回答。
- 用户停止、断网、401、403、额度不足、上游空正文、输出截断均有明确反馈；问题与部分输出可恢复。
- 手机软键盘不挡输入；中文组合输入不误发；上滑阅读不被拉回；长表格不撑破页面；键盘可操作按钮与选择器。

### 自动化与质量验证

1. 单元：盘引用/快照/上下文预算、模式路由、年份处理、状态机、协议解析、幂等与 usage 结算。
2. API/数据库集成：A 用户不能引用 B 的盘、会话、旧记录；跨设备并发、命盘编辑/删除、数据库失败、迁移重跑与分页。
3. 浏览器 E2E 全 mock 写入与 LLM：入口交接不自动发送、五态选择器、首问/追问/停止/重试/重答、刷新、切盘、登录回跳只恢复一次、旧记录查看。
4. 梅花、六爻现有 UI/请求/积分兼容回归；原八字详情“必须有 AI、必须五方面”的断言按新需求有意替换，不能直接全量更新截图掩盖差异。
5. 排盘算法对拍保持原结果；真太阳时/性别/零点边界等口径不因 UI 分工而改变。
6. 人工质量固定题集：初读、学业/职业条件差异、指定年份/月度、术语解释、连续追问、错误前提纠正。评审事实一致、直观性、连贯性、不过度断言，不拿文长或术语数量当质量。
7. 本规划未调用付费模型；实施中的实模型试验需明确样本量与费用范围，单独报告首字耗时、完成率、上下文正确率和每轮 usage，不伪造数值目标。

构建必须显式使用临时 outDir；仓库默认 Vite 输出为线上目录，不能当隔离测试。正式发布只能 `./deploy/sync.sh`，随后比对产物/容器哈希、HTTP 与浏览器验证；不探索修改 nginx/proxy_protocol。

## 十一、产品确认与实施边界

前三项已由用户确认，第四项区分已实现的旧解析回看与尚未建设的快照能力：

1. **纯排盘范围（已确认）**：严格模式，仅保留中性盘面、统计和时间表，移除旺衰、格局、喜用神判断及个人化吉凶文字；底层计算不变。
2. **游客（已确认）**：保留一次非综合解读，沿用签名 cookie 与 IP 闸门；登录恢复临时资料与问题，不自动付费发送。临时记录仅当前浏览器保存，不宣称已导入数据库或跨设备可用。
3. **首页入口（已确认）**：保持现有 iframe 弹窗与其余布局。独立带盘链接不替换首页入口。
4. **历史与快照**：保留旧解析只读回看。当前同盘历史仍基于既有 JSON 存储，独立会话、源盘快照及编辑/删除后的快照保留尚未实现，不将这些能力宣称为已完成。

确认后建议按 P0 → P1 → P2 → P3 → P4 → P5 执行。**先把对话承接能力做好，再从八字页撤下解析；不先拆入口让用户无处解读。**
