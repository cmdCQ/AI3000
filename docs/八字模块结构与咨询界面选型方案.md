# 八字模块结构与咨询界面选型方案

> 状态：最小版本已发布并完成关键线上核验，等待用户验收。本文基于回滚后的版本重新实施，不恢复已撤销实现。
> 验证：前端 132 项单元测试、后端 12 项测试、隔离浏览器 72 项、线上产物浏览器 38 项通过。写接口与模型均模拟；真实付费回答质量、真实登录后的新增咨询落库与扣费尚未实调用验收。发布使用 sync.sh 并重载后端，前端/容器哈希 27a4b232c576、后端/容器哈希 44404d398aab 一致；真实匿名咨询 API 返回 401。页面指纹无问题：首页变化为移除通用入口，选盘文案及卡片入口按新契约变化，详情游客文案不变、去除 AI 依赖。
> 当前实施范围：命盘卡片发起独立咨询、复用 assistant-ui 的 React 聊天原语、服务端咨询与轮次记录、详情只看盘、移除首页通用 AI 入口；通过关键测试后按授权发布供用户验收。正式专项提示词待用户提供；不调用真实付费 AI 进行测试。
> 本文为当前新方案；《八字排盘与AI对话分离方案》属于已撤销的历史方案，其实现记录与旧决定不自动沿用。

## 1. 结论先行

**四柱八字以命盘为入口；点命盘卡片查看排盘，点卡片上的“发起咨询”进入独立咨询页。**

- 首页移除通用“AI 对话”入口，不重做其他首页区域。
- 排盘详情不放“发起咨询”、咨询记录、预设问题、AI 解读等附加内容，不作为咨询中转站。
- 咨询页关联一张命盘，提供预设问题和自由输入；用户主动发送后才生成回答。
- 一张命盘可以关联多次独立咨询，不能等同于一场永久对话。
- 咨询页只通过“查看完整排盘”链接访问现有详情，不嵌入或折叠展示排盘。
- 前端保持当前 Vite 多入口 + React 架构；复用成熟聊天组件，不引入另一套完整 AI 平台。
- 最小版采用 assistant-ui 0.15.29 的原语与 LocalRuntime，自定义适配本站服务并使用本站 CSS；首问、连续追问、历史恢复、失败状态已通过隔离浏览器测试。Chatscope 不引入。

## 2. 已确认与待确认分开

### 2.1 已确认的产品方向

| 项目 | 决定 |
| --- | --- |
| 首页通用 AI 入口 | 移除 |
| 命盘卡片 | 点卡片看排盘；“发起咨询”为独立操作 |
| 排盘详情 | 只承担排盘查看，不增加咨询入口或其他咨询内容 |
| 咨询页的盘面 | 不嵌盘；提供“查看完整排盘”链接 |
| 开始回答 | 用户点击具体预设问题或主动发送，不自动生成 |
| 预设问题 | 面向用户的具体问题，服务端对应专用提示词 |
| 多次咨询 | 命盘是资料，一张盘不是永久绑定的一场对话 |
| 视觉与技术 | 本站整体风格；Vite + React；遵循 AGENTS.md；禁止重复造轮子 |

“详情不再放内容”在本文中指不放额外服务内容，不理解为把排盘数据本身删除或把页面清空。具体排盘字段的保留表仍须确认，不能由实施者自行删除。

### 2.2 本文建议、尚未确认

1. 咨询记录通过命盘列表工具栏的低强调“咨询记录”入口访问，不占列表顶部大块区域。
2. 排盘页保留出生资料、四柱、必要历法与大运流年数据；移出新 AI 生成操作，旧分析保留独立只读入口，不塞回排盘页。
3. 首问发送时创建正式咨询，进入空白咨询页不生成空历史记录。
4. 咨询记录筛选可在当前列表页内切换，避免再增加一个“咨询中心”页面。
5. 首版不开放编辑历史消息、分支重生成、上传、语音、工具自主执行等组件虽支持但当前不需要的能力。

游客权益、旧记录去向、排盘数据字段以及提示词内容尚待确认，不能因页面迁移而默认取消。

## 3. 为什么此结构与全站一致

首页目前以“命理 / 术数”区分四柱八字、梅花、六爻等业务。用户先选择要做的事，而不是先选择一个通用 AI 工具。

- 八字围绕长期命盘，可以看盘，也可以多次咨询。
- 梅花、六爻围绕一次事项起卦，沿用现有已认可流程。
- 一致的是“先明确对象，再按需解读”，不是强迫三个模块长得一样。
- 本轮不改变梅花、六爻的解卦位置、提示词、权益或界面。
- “AI”是八字咨询的实现能力，不另成为与四柱八字平级的产品中心。

## 4. 页面与导航：只保留必要路径

```text
首页
└─ 四柱八字：命盘列表（沿用当前选择页位置）
   ├─ 新建命盘 → 现有出生资料表单 → 回到列表并定位新卡片
   ├─ 点命盘卡片 → 完整排盘 → 返回原列表位置
   ├─ 点“发起咨询” → 已带好命盘的新咨询页
   │                    └─ 查看完整排盘（辅助查看，不从排盘页再发起咨询）
   └─ 咨询记录（建议的列表内视图） → 继续对应的既有咨询
```

- 不设“八字介绍 → 选择服务 → 再选命盘”这类中间步骤。
- 不把点击卡片改为进聊天，不依赖解释文案弥补跳转错位。
- 首页仍叫“四柱八字”；列表标题仍为“四柱八字”，说明建议为“查看命盘，或选择一张命盘发起咨询”。
- 卡片上的“发起咨询”必须带当前盘，不再弹一次选盘框。
- 返回命盘列表保留滚动位置、原视图和筛选条件。
- 咨询中查看排盘采用明确的辅助浏览方式；建议链接新标签打开，原对话与草稿留在原页，手机和普通同页返回也应有恢复保护。是否新标签以原型确认为准，不额外为排盘页添加咨询按钮。

### 4.1 建议路由契约（路径待实施前统一）

| 用途 | 建议 |
| --- | --- |
| 命盘列表 | 保留 `/select-chart/?type=charts`，不为改版强制迁移公开 URL |
| 完整排盘 | 保留 `/my-charts/?id=…` |
| 新咨询 | `/bazi-consult/?chartId=…`，首次发送前无正式咨询 ID |
| 继续咨询 | `/bazi-consult/?consultationId=…`，后端根据咨询查命盘，不信任第二个可篡改 chartId |
| 咨询记录 | 列表内 `view=consultations`，可分享/返回，不另建全站聊天中心 |

新咨询使用一个 React 页面入口，不另建游客 HTML、iframe 或复制旧聊天脚本。`/ai-chat/` 的旧链接和历史不能直接删除，需在旧数据承接方案确认后决定只读或引导行为。

## 5. 界面规格：本站的咨询页，不是套模板换 Logo

### 5.1 复用现有主题事实来源

现有 `src/app/shared/css/tokens.css` 已定义玉青与净白主题：

| 用途 | 必须复用 |
| --- | --- |
| 页面 / 卡片 | `--bg: #fcfcfa` / `--bg-card: #ffffff` |
| 主操作 | `--gold: #1f6b5e`、`--gold-ink`，这里 gold 是历史命名，不代表金黄色按钮 |
| 暖金 | `--warm-line` / `--gold-line` 仅作细线装饰，不作大块底色 |
| 文字 | `--text`、`--text-dim`、`--text-muted` |
| 字体 | 标题使用 `--serif`，正文和输入框使用 `--sans` |
| 尺寸 | 页面最大宽度建议沿用 `--page-max: 680px`；不直接修改全站 `--chat-max` |
| 交互 | `--tap-min: 44px`、现有焦点与 reduced-motion 规则 |
| 间距 / 圆角 | `--space-*`、`--r-*`，不新增一套品牌色和无规律数值 |

不得引入默认蓝紫渐变、纯黑控制台、满屏聊天侧边栏或第三方品牌导航。不得以“原语没有样式”为理由交付无样式页面。

### 5.2 命盘卡片

```text
四柱八字                         ＋ 新建命盘
查看命盘，或选择一张命盘发起咨询

┌────────────────────────────────┐
│ 生肖  张三       四柱简要信息     › │
│       性别 · 出生日期 · 时辰       │
│                        [发起咨询] │
└────────────────────────────────┘
                       咨询记录（低强调入口，待确认）
```

- 保留现有卡片的白底、暖金左细线、玉青操作，不再重设计选择页。
- “发起咨询”有独立点击与键盘焦点；触屏可放卡片右下，不能挤坏姓名与时间。
- 实现上外层是非交互容器，详情链接覆盖非操作区域，咨询链接独立同级；**禁止 `<a>` 内再嵌按钮或链接**。两项均能 Tab/Enter 和新标签打开，不靠 stopPropagation 修补嵌套交互。
- 缺少命盘、加载失败、登录过期沿用现有五态及重试；不可显示空列表掩盖错误。

### 5.3 新咨询首屏

```text
← 四柱八字                 咨询记录

张三的八字咨询             查看完整排盘
男 · 1990年5月17日 14:30（示例）

你想先了解什么？
已关联这张命盘，无需重复填写出生信息。

[我的命局有哪些主要特点？]
[事业发展适合重点考虑什么？]
[感情与相处模式有哪些特点？]
[今年有哪些值得关注的变化？]

    也可以直接输入你想问的问题
──────────────────────────────────
[输入问题……                     发送]
计费规则说明 / 当前可用额度（按现有规则）
```

- 问题只是界面示例，不是最终提示词或保证分析质量的承诺。
- 不自动请求模型、不自动扣费、不在首次进入时创建一堆空咨询。
- 不显示一段伪装成 AI 已读盘的欢迎答案；“已关联”是加载成功的系统状态。
- 建议最多先放四个具体问题，移动端单列、桌面可两列；不恢复旧五个切换即替换正文的标签面板。
- 点击具体问题即发送该问题；按钮附近说明“点击问题开始回答，按现有规则计费”，不能让人误认为只是切换栏目。
- 首次发送后大块引导退出正文区，输入框保留小型“常见问题”入口。

### 5.4 对话中与历史

- 顶部始终标识当前命盘与咨询主题，长姓名截断可展开，不显示完整私密出生地。
- 用户消息用玉青浅底紧凑气泡；AI 正文以白底可读排版为主，不把整篇长回答压进窄气泡。
- 中文正文建议 15–16px、行高 1.8；限制长表格、链接横向溢出；Markdown 不渲染未经清洗的原始 HTML。
- 输入区在视口底部，适配安全区和手机键盘；正文底部留足空间不被覆盖。小屏不设常驻侧栏。
- 回答中显示停止操作；用户翻看前文时不强行拉回底部，提供“回到最新”。
- 咨询记录建议显示“主题 / 命盘 / 最近时间”，不以全部叫“新咨询”的空记录充数；首问可确定性截取为标题，无需额外付费模型命名。
- 新话题创建新咨询；继续历史使用原咨询 ID。聊天中不直接切换成另一张命盘，防止串盘。

## 6. GitHub 候选核查

核查方式：官方仓库 README、package.json、官方适配文档与迁移声明；未安装依赖、未启动样例、未进行实际渲染。分支内容会变化，正式采用必须固定版本并复核许可证及依赖。

### 6.1 assistant-ui：首选进行隔离适配验证

- 官方包 `@assistant-ui/react` 查阅版本为 `0.15.29`，MIT；声明 React / ReactDOM `^18 || ^19`，ESM。
- 本站当前 React `^19.3.1`、Vite `^8.3.4`、ESM，声明层面相容；不是实际集成已通过。
- 官方 `LocalRuntime` 通过 `ChatModelAdapter.run({ messages, abortSignal })` 接自定义 HTTP 后端，支持历史等适配器，不要求采用 Assistant Cloud。
- 可组合 Thread、Message、Composer 等原语，采用本站 CSS；不运行会默认铺入 Next/shadcn 风格整套模板的脚手架。
- 官方 Next 示例中的 `use client` 不是迁移到 Next 的产品理由；Vite 可采用浏览器 React 入口，实际包导出与打包仍需验证。
- 可复用消息状态、流式交互、取消、自动滚动等通用能力；持久化归属、积分、命盘提示词仍由本站负责。
- 官方流式适配支持 `async *run(...)`；每次 yield 的文本应是累积完整内容，不是单个 delta。需要在本站适配器统一处理协议和状态，不让视图组件各自拼流。包依赖中包含 assistant-cloud，但不等于必须使用云服务。
- 维护核查：官方仓库有持续的版本与提交更新；采用时应再次核对 release/CI/安全通告，不以星数作为质量结论。
- 风险：依赖包含 Radix、Zustand、Zod、assistant-stream 等，不是无成本小组件；部分 thread API 有 unstable 命名。需要锁版本、限制使用面、测产物增量，不直接跟随 latest。
- `LocalRuntime` 默认内存状态不等于服务端保存。必须实现历史适配与刷新恢复，不能把库带 ThreadList 误称网站已有多会话。

来源：
- https://github.com/assistant-ui/assistant-ui
- https://raw.githubusercontent.com/assistant-ui/assistant-ui/main/packages/react/package.json
- https://www.assistant-ui.com/docs/runtimes/custom/local-runtime
- https://www.assistant-ui.com/docs/api-reference/adapters/persistence

### 6.2 Chatscope：界面备选，不作为首选 AI 状态方案

- 官方 `@chatscope/chat-ui-kit-react` 查阅版本 `2.1.1`，MIT，React peer 包括 19，提供 ESM。
- 提供容器、消息列表、输入框等；可接任何自有后端。
- 默认样式来自独立样式包，需要主题映射与输入行为核查，不能直接把默认外观搬进来。
- 缺点：更偏通用消息界面；模型终态、失败、重试、历史同步仍需实现较多，无法仅靠 UI Kit 消除自研聊天状态逻辑。
- React 19 peer 声明不代表中文 IME、触屏滚动已在本站验证；仓库开发依赖仍有 React 18，需实际测试。

来源：
- https://github.com/chatscope/chat-ui-kit-react
- https://raw.githubusercontent.com/chatscope/chat-ui-kit-react/master/package.json
- https://chatscope.io/storybook/react/

### 6.3 Vercel AI Elements：暂不选旧仓库作为本次基座

- 官方说明是基于 shadcn/ui 的源码组件，安装路径涉及 shadcn/Tailwind，本站目前都未采用。
- 文档面向 Next + AI SDK，但不能据此断言每个组件技术上只能用于 Next；真正成本是新增样式体系与传输适配。
- 官方 README 公告项目将迁到 shadcn/ui，旧项目预计在 2026 年 11 月底弃用。该维护迁移信号比星数更影响当前选择，应采用前再次核实。
- 组件复制到仓库后仍需自己维护，不能把复制大量组件当“零自研”。暂不为此改全站 CSS 技术栈。

来源：
- https://github.com/vercel/ai-elements
- https://raw.githubusercontent.com/vercel/ai-elements/main/README.md

### 6.4 LibreChat：完整平台，不适合本轮嵌入

- 提供完整会话、多模型、用户、工具与自托管部署，是应用而非少量界面组件。
- 本站已有账号、积分、命盘和后端；整套引入要解决双重账号、数据存储、权限、计费和部署归属。
- 即使可配置相同模型接口，也不代表能直接复用本站命盘权限与计费。
- 不 fork 整个平台只为取得聊天皮肤。仅作为功能和交互参考，不新增独立服务。

来源：https://github.com/danny-avila/LibreChat

### 6.5 选型判断与证据边界

| 候选 | Vite/React 接入方向 | 网站风格控制 | 后端侵入成本 | 当前建议 |
| --- | --- | --- | --- | --- |
| assistant-ui | 原语 + 自定义 runtime 适配 | 高，可自有 CSS | 中，仍需持久化/流契约 | 首选验证 |
| Chatscope | 消息 UI + 自有状态 | 可定制但需改默认样式 | 中至高，AI 语义需自己补 | 备选 |
| AI Elements | 源码组件 + 配套样式 | 可控但增加 Tailwind/shadcn | 取决于 SDK 适配 | 暂缓 |
| LibreChat | 完整应用整合 | fork/主题改造 | 高 | 不采用整套 |

当前没有安装/性能数据，不能给出“最轻”“绝无冲突”“已适配”的承诺。正式锁定前检查发布与安全通告、许可证文本及传递依赖；保留 MIT 等要求的版权声明，与本项目 GPL-3.0-only 分发方式一并核查。若 assistant-ui 需要大幅改现有后端或难以主题化，应回到选型，不默默改成自研聊天框。

## 7. 实现架构建议（仅规划）

### 7.1 保持现有构建方式

- 当前是 Vite 自动收集 HTML 多入口，React 19 + ESM，并非 Next 应用。
- 咨询页放入一个新的页面入口，由 React 从 createRoot 管理完整树；不复制现有千行 imperative 聊天逻辑，不用 innerHTML/全局 onclick 管理新消息。
- 不引入 Next 服务、外部聊天 iframe、第二套用户系统和单独的游客页面。
- 旧通用聊天与新八字咨询的过渡路径清楚区分；旧链接/旧记录承接完成前不得删库删记录。

建议职责拆分（名称可在实施时简化，不预造框架）：

```text
bazi-consult/
  main.jsx                 页面入口与组合
  ConsultationPage.jsx     首屏/正文/错误状态
  components/              命盘标题、预设问题、记录面板
  runtime/                 assistant-ui 模型/历史适配
  api.js                   本站接口访问与契约映射
  style.css                仅本站主题与页面布局
shared/
  现有 tokens、auth、可复用的已核实组件
server/
  八字咨询领域服务          归属/会话/命盘快照/提示词
  共享模型与结算服务        复用现有能力，禁止第二套积分逻辑
```

不要同时用 runtime 与另一套全局数组保存两份权威消息；服务端保存的会话为持久事实，runtime 负责当前显示，通过适配器同步。

### 7.2 必须真正支持独立咨询

当前后端 `chat_history` 是按用户存一份 JSON；`/api/chat/send` 目前无可用八字分支，普通追问还会截历史至每条 200 字。不能直接改入口就称完成。

建议新增专门的咨询持久结构（需数据库迁移评审）：

- consultation：id、user_id、chart_id、title、命盘快照/版本、提示词版本、状态、时间。
- message/turn：所属咨询、顺序、角色、内容、request_id、状态、usage/结算状态。
- 每次查询和发送同时校验账号与咨询归属；只凭 chartId 或客户端完整命盘都不够。
- 同盘不同咨询互不共享消息；历史加载有分页，不按全用户固定 200 条截断混存。
- 命盘编辑后，旧咨询沿用创建时快照，界面提示资料曾更新；新咨询使用新资料。删除命盘对旧咨询的处理待确认，默认不得级联抹除历史。

这是“一张盘多次咨询”要求产生的必要成本，不是组件库可代替的能力；不能再次以给 JSON 加 type 标签冒充独立会话。

### 7.3 提示词结构

```text
服务端基础规则
＋ 经权限校验、按本站算法重建的命盘事实
＋ 当前咨询的命盘快照与时间基准
＋ 预设问题对应模板（仅首问/明确选择时）
＋ 本咨询的有效历史
＋ 用户原始问题
```

- 客户端传问题文本与 presetId，不传可任意覆盖的系统提示词；presetId 服务端白名单解析。
- 预设内容集中定义 id、可见问题、模板版本，不写散在 JSX 和服务器多个分支。
- 命盘事实、规则推导与用户描述明确区分；不把现有“综合评分+固定全部栏目”模板原样塞回去。
- 后续追问稳定关联同一盘，但不每次重复执行首问的全套模板。
- 年份、日期、年龄不触发自动梅花起卦，不向八字用户索要三个数字。
- 真太阳时及历法口径沿用现有权威算法，不在前端/适配器重算。是否修正既有口径是独立任务。
- 本文只规定模板结构与责任边界，不编造用户尚未提供的正式分析提示词。

### 7.4 流式、失败和积分

当前声明 text/event-stream 不等于已有标准 SSE 帧。建议新八字链路使用显式版本协议，由适配器映射 runtime；不强改梅花/六爻现有调用。

至少区分：正文 delta、usage/积分、最终 completed/partial/stopped/failed、保存结果。错误说明不进入 AI 正文，积分尾巴不靠正则从回答里扒取。

- 401 登录承接；403 无额度；404 无权访问/不存在；503 服务或数据库故障。
- 网络断开、主动停止、长度截断不能显示“回答完成”；保留已输出内容并标明未完成。
- 额度、模型调用、结算沿用本站规则与服务，不因复用新 UI 旁路计费；中断是否计费须按现行规则明确告知，不擅自承诺免费。
- 首问幂等键防双击/超时重试重复创建与扣费；同咨询发送序列化或拒绝并发，避免消息覆盖。
- 保存失败与结算失败必须可见、可追查，不把前端成功动画当持久化成功。
- 取消信号传到服务器上游；用户刷新后的恢复以服务端状态为准。

## 8. 不可遗漏的状态与数据保留

| 状态 | 预期 |
| --- | --- |
| 新建咨询未发送 | 仅选盘、预设问题与草稿；不扣费、不写空记录 |
| 有历史咨询 | 恢复该次咨询；不重新出现大块首次引导 |
| 命盘加载失败 | 禁止发送，明确重试；不能只凭 URL 显示“已关联” |
| 输入中文 | IME 组合确认不误发送；Enter/换行规则有提示 |
| 多次点击问题 | 一次请求；生成中禁重复发送 |
| 查看排盘再返回 | 对话、滚动、草稿可恢复；不再次自动生成 |
| 会话 A/B、命盘甲/乙 | 消息、提示词、积分归属不串 |
| 无账号或登录过期 | 沿用权益要求；恢复意图与草稿，但不登录后自动发送 |
| 旧八字分析 | 保留数据；只读入口位置待确认，不塞进纯排盘详情 |
| 旧通用聊天 | 移除首页入口不等于删除历史；承接位置待确认 |

游客现有一次非综合解读不能因架构改造悄悄消失。具体是否转入同一咨询页，以及临时资料来源、可问范围、登录后保存策略，要在实施前单独确认；本方案不重建上轮已撤销的独立游客页面。

## 9. 分阶段验收，不再“代码写完才看界面”

### 阶段 A：产品和界面确认

- 确认本文第 10 节问题。
- 同时展示命盘列表、咨询首屏、对话中、记录视图的低保真结构与本站风格样稿。
- 先审手机 390px 和桌面 1280px；没有界面确认，不进行全链路迁移。

### 阶段 B：选型技术探针（获准后）

- assistant-ui 固定版本，单独工作分支/临时产物，不运行脚手架覆盖现有项目。
- 用模拟 API 验证 Vite 构建、纯 JS 消费、CSS 原语、流式、停止、错误、历史注入、键盘与滚动。
- 输出依赖与 gzip 产物增量、真实兼容问题、第三方许可证清单；现在不凭感觉规定虚构数字。
- 若需强制 Next、云存储或大范围全站样式重写，则不接受该接入方式，评估备选。

### 阶段 C：会话与接口契约

- 先实现与测试命盘归属、独立咨询、快照、幂等、历史与计费终态；模型与写入全部 mock。
- 提示词结构与正式模板分别审查，预设问题与服务端模板一一对应。
- 数据迁移应可回退，保留旧表与记录；不同时删除旧能力和开发替代链路。

### 阶段 D：页面整合与回归

- 前端只用统一 runtime 和适配器，界面完全映射本站主题。
- 测正常/失败/权限/空态、中文输入、停止与重试、刷新恢复、历史分页、同盘多次咨询和切盘隔离。
- 检查 390/500/1280px 长姓名、长消息、表格和键盘，无横向溢出与遮挡。
- 回归首页其他区域、命盘创建/编辑/删除、梅花和六爻，不盲目更新无关截图基线。

### 阶段 E：获准发布后迁移入口

- 发布前留可恢复的源码与产物基线，明确本次变更，不依赖现场从 dirty tree 猜回滚范围。
- 默认 Vite 输出是 live build，测试必须显式临时 outDir；只用 deploy/sync.sh 发布。
- 验证产物/容器哈希、HTTP、浏览器流程与 webprobe 预期差异；后台代码加载与数据库迁移另核验。
- 新咨询与旧记录承接可用后，再撤首页通用入口和详情生成操作；保持用户看到的是一套明确新流程，不长期并行两套新解读入口。
- 本轮只规划，不执行上述构建、迁移或发布。

## 10. 下一次讨论只需先定这四件事

1. **记录入口**：是否接受命盘列表里的低强调“咨询记录”，不放顶部“最近咨询”大区块？旧八字分析与通用聊天历史是否也在这里分类型只读访问？
2. **排盘字段**：确认保留哪些原始数据；“不增加任何咨询内容”已经确定，但不据此擅自删除全部原有盘面。
3. **游客权益**：保留现有一次非综合机会时，从哪里提供临时资料，怎样与已保存命盘严格隔离？
4. **预设问题与模板**：首屏先放哪些具体问题，正式提示词由谁提供，哪些题目受权益限制？

以上未确定项不妨碍先讨论结构，但会阻止完整产品实现。不得把规划文档的技术建议当成用户已授权的删除、权益变化或上线指令。
